# 2026-09-30

## 项目改名：JellyfinMac → Overtone（泛音）

产品名 **Overtone**（泛音：基音之上叠加的谐波）。非官方客户端，副标题形式里才出现 Jellyfin。

### 关键结论：产品名与内部标识必须解耦

| 层面 | 值 | 动不动 |
|---|---|---|
| `.app` 名 / 访达·启动台显示名 | `Overtone` | ✅ 改了（`build-app.sh` 的 `APP_NAME` + Info.plist 的 CFBundleName/DisplayName） |
| 界面文案（窗口标题、登录页、侧栏） | `Overtone` | ✅ 改了（需重新编译才生效） |
| Bundle ID | `com.jellyfin.mac-client` | ❌ 不能改：钥匙串存密码的 `service` 就是它（`KeychainHelper`），改了要重新登录 |
| 本地数据目录 | `~/Library/Application Support/JellyfinMac/` | ❌ 不能改：`playlists.json` 在这，改了会丢播放列表 |
| Swift target / 目录 / 可执行文件名 | `JellyfinMac` | ❌ 未改：要连 Package.swift + 两个脚本一起动，且本机没 Xcode 无法编译验证 |

**通用经验**：给 App 改名时，先分清「产品名」和「标识符」。bundle ID / keychain service / 数据目录 / 可执行文件名都属于标识符，跟着改名会丢登录态和本地数据。

### 踩坑：带透明通道的 icns 会被 macOS 套灰底板

这台机器上，icns 只要有透明像素，IconServices 就会在图标后面垫一层浅灰底板，并把图案缩到原来的 ~68%（实测 824 → 558）。**项目旧图标也有这个毛病**，不是新图标引入的。

对照实验（用 `NSWorkspace.shared.icon(forFile:)` 取渲染结果，量彩色区域 bbox）：

- 旧图标（透明圆角方块）：彩色 bbox 650，中心灰
- 新图标蒙版版（透明）：彩色 bbox 558，中心灰
- 新图标满出血版（不透明）：彩色 bbox **824** ✅

**结论**：主图必须满出血不透明，系统自己会裁成标准形状（824x824 连续曲率圆角方块 + 100px 留白）并补投影。实测渲染出的 alpha 与系统 App（Music.app）逐像素差异为 0。

### 环境限制：本机无法编译

`xcode-select -p` → `/Library/Developer/CommandLineTools`，没有 Xcode。SwiftUI 的宏插件（`SwiftUIMacros`，`@State` 等依赖它）随 Xcode 提供，所以 `swift build` 必然报：

```
error: external macro implementation type 'SwiftUIMacros.StateMacro' could not be found for macro 'State()'
```

因此本机只能：改 Info.plist / 换图标 / 重签名 / 手工重组 bundle；**改 Swift 源码后无法验证编译**。
