## UI v3 落地到 Swift（按 UI-Redesign-v3.md + preview 重写界面）
- 范围：令牌层（§7 材质 + 氛围层）→ 组件层（§4.5 状态机 / Toast / 空态 / 骨架 / Chip / 44pt 热区）→ 页面层（首页 / 列表 / 详情 / 设置 / 正在播放 / 迷你播放条 / 主壳）。共 23 个文件、+3045/−997。
- **Liquid Glass 双层结构**（Theme.swift）：`GlassMaterial`(thin/regular/thick) + `.glassPanel(_:cornerRadius:elevation:tint:)`。macOS 26+ 走 `Color.clear.glassEffect(.regular, in: shape)`（已用 `swiftc -typecheck` 验证 API 形态：`glassEffect(in:)`/`.tint()`/`.interactive()`/`GlassEffectContainer` 都在），13–25 回退 `.ultraThinMaterial/.regularMaterial/.thickMaterial`。
- **性能预算的取舍（重要）**：§7.2 规则 4 要求同屏 blur 层 ≤4，所以只有**大面板**（侧栏/顶栏/播放条/抽屉/弹窗/Toast）走真材质；**成排出现的小控件**（图标按钮/次级按钮/输入框/分段容器/胶囊）用 `.glassControl()` —— 半透明表面 + 玻璃描边 + 顶部 1px 高光，**不做 blur**。底下就是氛围层，观感与磨砂玻璃一致而代价为零。
- **氛围层**（`AmbientWash`）：4 枚椭圆色斑 + 底色渐变。CSS `radial-gradient(rx ry at x y, color, transparent 62%)` 的等价写法是 `Circle().fill(RadialGradient(endRadius: radius*0.62)).scaleEffect(x: aspect)`；**endRadius 一开始写成整个 radius，色斑扩散过满、整页偏色**，乘 0.62 后才与预览一致。
- 悬浮布局（§7.2 规则 2）：侧栏 `padding(.leading,10).padding(.vertical,10)`、顶栏/播放条 `padding(.top/.bottom,10).padding(.horizontal,12)`，统一 `Radius.md`(10)。窗口顶部不再需要 28pt chrome 条 —— 悬浮侧栏（10 起）正好把红黄绿三键包进面板内。
- **`appGlassSurfaces` 环境值**：设置窗口是独立 scene、没有氛围层，玻璃在那里只会得到「白底上的半透明白」（分段控件轨道直接看不见）。用环境值把设置场景的玻璃关掉，控件回落 `surfaceSunken` + `borderDefault`。
- **`appReduceTransparency`**：`NSWorkspace.shared.accessibilityDisplayShouldReduceTransparency` + `accessibilityDisplayOptionsDidChangeNotification` 监听；开启后玻璃换 `surface` 实底 + 描边，氛围层压到 30% / 饱和 35%。注意 `com.apple.universalaccess` 域受 SIP 保护，**没法用 `defaults write` 模拟**，验证要靠临时环境变量钩子。
- **命中区 ≥44pt 的写法**：`.padding(inset).contentShape(Rectangle()).padding(-inset)` —— 视觉与布局占位都不变，只有热区变大（`hitExpand(from:to:)`）。
- 侧栏选中态按预览改成 `brandTint` 底 + `brandText` 字 + semibold（原来是 `brandGradient` 实底白字）；轨道栏改纯图标 + 顶部汉堡（抽屉入口）。
- **顺手修的真 bug**：`MainView.bootstrap` 只等 `APIClient.baseURL != nil` 就 `loadLibraries()`，但 `baseURL` 在 `restoreSession` 里**早于** `/Users/Me` 赋值 —— 启动页不是首页时（视图构建更快）会撞进这个窗口，`loadLibraries` 因 `user == nil` 直接 return，媒体库 ID 永远解析不出来，整页空白且无重试。修法：bootstrap 等到 `user != nil`、`libraries` 为空时退避重试 5 次；`MusicDataStore.ensureLoaded()/reload()` 在 `libraryId == nil` 时自己补解析。
- 表头吸顶：`TrackTable` 拆成 `TrackTableHeader` + `TrackTableRows`，详情页放进 `LazyVStack(pinnedViews: [.sectionHeaders])` 的 Section；吸顶表头按 §7.2 用 `glassPanel(.thick, cornerRadius: 0)`。
- 弹窗归属：主窗口与设置窗口各挂一份 `.dialogHost()`，`ConfirmRequest` 记录**发起窗口**（`NSApp.keyWindow ?? WindowManager.mainWindow`），只有那个窗口渲染，否则同一请求会弹两次。
- 验证手段（锁屏环境下）：`screencapture -l<windowid>` 仍能抓到窗口内容（`caffeinate -u -t 1` 唤醒显示器即可），但**键鼠事件进不去**（前台被锁屏占住，`lsappinfo front` 恒为别的 App，AX 树也不暴露 SwiftUI 内容）。于是用 `defaults write settings.startPage/theme + NSWindow Frame …` 改启动页/主题/窗口宽度后重启截图；设置页用临时环境变量钩子把 `SettingsView` 挂进 RootView 截。
- **构建耗时坑**：release + WMO 下改任何一个文件都是全量重编（~16 min）。快速验证循环 = `swift build`（debug，增量 ~6s）+ 把 `.build/debug/JellyfinMac` 拷进 `build/Overtone.app/Contents/MacOS/`（保留 bundle 上下文，UserDefaults 域才对；直接跑 `.build/…/JellyfinMac` 会掉进登录页）。
- **宏替身插件的坑**：`tools/SwiftUIMacrosShim` 的 `@State` 展开会在属性行尾拼接代码 —— 属性声明后面**不能跟行尾注释**，否则注释把生成代码吞掉，报 `expected ')' in expression list` 且定位指向无关文件。
- 服务端数据现状（非代码问题）：`/Users/{id}/Items?IncludeItemTypes=MusicAlbum` 对该音乐库返回 `TotalRecordCount: 0`，而 `Audio` 有数据 —— 「最近添加」空态是真实反映，不是 UI bug。另外 Jellyfin 12 的鉴权要 `Authorization: MediaBrowser Token="…"` 头，`?api_key=` 查询参数已不生效。

## 布局溢出修复 + 侧栏悬浮面板（用户反馈：页面顶出窗口右边缘）
- **症状**：顶栏搜索框、播放条右半、页面右边缘全被窗口右边缘裁掉；用户描述「整体页面宽度变窄，把玻璃面板右侧覆盖」。
- **根因（量出来的，不是猜的）**：`MiniPlayerBar` 三区用固定宽度（左 220 / 右 220 + 控制区 min 160），最小宽度 ≈870pt；而 900pt 窗口 − 侧栏 210 = 内容列只有 690pt。`HStack` 遇到「子视图最小宽度 > 可用宽度」会把整列按最小宽度铺开并溢出到窗口右侧 —— 于是同列里的顶栏、页面一起被顶出去。截图实测内容列 ≈790pt（≈播放条最小宽度）而不是 690pt。
- **修法**：① 播放条改 `GeometryReader` 按**自身实测宽度**降级（≥820 三区 / ≥940 时间码 / <620 紧凑），左右区改 `maxWidth`；② `MainView` 给内容列显式宽度（窗口宽 − 侧栏块）作硬约束；③ 修好后 900pt 窗口下播放条落「两区 + 队列按钮」，与规范 §6 W1 行一致。
- **侧栏「悬浮化」的坑**：`.padding(.leading,10).padding(.vertical,10)` 原本写在 `.glassPanel(...)` **里面**，玻璃把 padding 一起铺满 → 面板贴住窗口左/上/下边缘（量像素确认：面板从 y=2px 就开始了）。padding 移到 glassPanel 之外才真正悬浮。抽屉同样问题，一并修。
- **红黄绿三键**：面板外边距 10 + 圆角 10 → 圆角圆心 (20,20)，系统默认首键 (8,8) 落在圆角外侧（三键会悬在氛围层上）。`WindowManager.moveTrafficLights` 用「窗口坐标算目标 → 换算回按钮父视图坐标系」（不依赖 flipped），完整侧栏 (20,20)/gap 7，图标栏 (14,20)/gap 4（64pt 面板才装得下 16×3 的三键）；`MainView` 用 `.onChange(of: rail)` 同步形态，`ConfigNSView` 监听 didResize 重摆（标题栏会随缩放重置按钮位置）。`windowChromeHeight` 28→34。
- **验证**：debug 增量编译 + 拷进 `build/Overtone.app` 重启；用 `screencapture -l<windowid>`（`swift /tmp/winid.swift` 取 id）+ AppleScript 改窗口尺寸，跑 520/620/700/900/1000/1200/1500 七个宽度 × 首页/资料库/播放列表/正在播放 四个页面截图目检。播放条只在有 currentTrack 时渲染，用临时环境变量钩子（`OVERTONE_DEBUG_TRACK` 塞一条 stub 队列、不发声）截图后已删除，`git diff` 确认 MusicPlayerModel 无残留。
- **踩坑补充**：`swift build` 必须带宏替身插件参数，否则 `@State` 全量报错（`-Xswiftc -load-plugin-executable -Xswiftc "<shim>/SwiftUIMacros#SwiftUIMacros"`，见 scripts/build-app.sh）；`System Events` 的 ⌘1–⌘5 keystroke 进不去 SwiftUI 的 `KeyboardShortcutHandler`（截出来三张图 md5 相同），改页面要用 `defaults write com.jellyfin.mac-client settings.startPage` + 重启。
