# 2026-10-14

## 修两个用户报的 bug（纸墨 + 侧栏高亮）

用户报：① 「选中左侧播放列表，选中提示仍然在上方的播放列表而不是下方选中的播放列表」；
② 「纸墨主题选中后无法看清文字」。两条都复现并修掉，改动集中在
`Views/MainView.swift` 与 `Theme.swift`（+42/−14 行级别，无新文件）。

### ② 的根因不是「纸墨配色」而是 `textStyle` 的颜色默认值
`ScaledTextStyleModifier.body` 无条件写 `.foregroundStyle(color ?? Theme.textPrimary)`。
这个修饰符**直接作用在 Text 上**，于是它盖掉祖先容器的颜色 ——
侧栏选中行本意是「墨块 + 纸字（v4 §4.3）」，实际渲染成**墨块 + 墨字**，文字整个消失
（2x 截图：选中行文字区像素 min=max=28，一个亮像素都没有）。
修法：`color == nil` 时**不写颜色**（继承外层），要 textPrimary 就显式传 ——
全仓 185 处 `.textStyle(` 里 180 处本来就显式传色，5 处不传的全部都是「想继承」：
侧栏行、`MusicLibraryView` 的「播放全部」按钮标签、3 处 `.foregroundStyle(Theme.danger)` 错误文案。
**同一根因的第二个受害者**：`PrimaryButtonStyle` 纸墨分支「墨底纸字」的按钮，
标签被压成墨色 → 库页「播放全部」在纸墨下只有一个 ▶ 图标、没有文字（截图复现）。
玻璃分支同样中招：库页「播放全部」是**深墨字压在信号红渐变上**（对比度约 2:1）。

### ① 的根因：侧栏高亮用 `ContentPage.navRoot` 硬映射
`navRow` 判 `selected.navRoot == page`，而 `navRoot` 把 `.playlist` 映射回 `.playlists`
→ 一级「播放列表」永远抢走高亮，列表行自己永远不亮（还顺带把「首页点开专辑」错亮成资料库）。
修法：详情页的高亮归属改由**导航栈**决定（`sidebarHighlightRoot` = 栈里那一层一级页，
与内容区常驻层的 `activeTab`、面包屑 `parentTitle` 同一套归属），播放列表行按 **id** 自认
（整值比会被增删曲目/同步打断）；完整侧栏下「选中列表行」与「一级项」互斥，一次只亮一行。
两种退回一级项的例外：① 图标栏（窄窗没有列表行可亮）；② 分组折叠着而当前列表不在可见 6 条里
（不让侧栏出现「一个指示器都没有」）。

### 刻意不改的地方（留给用户拍板）
玻璃模式的侧栏选中行标签**保持原样**（深色字 + 强调色图标）：README/v3 契约写着「玻璃取值与 v3
逐字节一致」，v3 实机截图（docs/screenshots/04-playlists.jpg）也是深色字；但 v3 预览 CSS
`.sb-item.active{color:var(--brand-text)}` 与代码旧注释都说该是强调色字 —— 两者本来就矛盾，
这次只修纸墨，在 `SidebarNavRow.labelColor` 注释里记了这个分歧。

### 截图工具链的坑（下次直接用）
- `System Events` 的 `click at {x,y}` 能驱动 SwiftUI 按钮；**`AXPress`（`actions.byName("AXPress").perform()`）
  返回 success 但 SwiftUI 按钮不响应** —— 自动化点击只能用坐标点击。
- 窗口被遮挡时 `screencapture -l <wid>` 会截到「上一次合成」的画面（表现为按键无效、图不变），
  必须先把目标实例 `frontmost` 再截；用户在用机器时会被微信等抢前台 → 截图前要重试/校验。
- 玻璃是半透明材质，**整窗逐像素 diff 天然有 9% 量级的噪声**（背后内容不同），
  A/B 只能比「目标区域」或「字形核心色」，不能比整窗。
- 截图脚本：`/tmp/ot-verify2.sh`（带遮挡重试）、`/tmp/ot-axpos.js`（按 AX 位置算点击坐标）。
- **两个同 bundle id 的实例，AX 认不出第二个**：`System Events` 的 `applicationProcesses` 按 bundle id
  去重，永远只返回「已注册的那个」（使用者 `/Applications` 里的实例），
  `whose({unixId: pid})` 因此指向错误进程 —— 用 AX 给开发实例定坐标/点击会打到使用者窗口上。
  正解：**完全不依赖 AX** —— 窗口矩形用 `CGWindowListCopyWindowInfo` 按 pid 取（`/tmp/ot-win`），
  「点击点上最顶层的窗口是不是目标进程」也用 CGWindowList 判（`/tmp/ot-at`），
  置前用 `NSRunningApplication.activate`（`/tmp/ot-activate`）。点击前必须断言 owner == 目标 pid，
  否则宁可中止（使用者窗口与开发实例窗口位置完全相同，误点就等于在人家正在用的 app 里乱点）。

## 正在播放页三处调整（用户当天追加）
1. **封面 / 歌词切换时上下两块不动**：原来是 `if showLyrics { LyricsPane } else { coverPane }`
   放在 VStack 里，两块高度不同 → 上面的分段控件与下面的进度条 / 控制键整体位移。
   改成封面永远在布局里（`opacity(0)`），歌词走 **`overlay`**（overlay 不影响父视图尺寸）→
   这一块高度恒等于封面块。`LyricsPane` 的 `.frame(height: 260)` 改成 `.frame(maxHeight: .infinity)`，
   歌词填满封面那一格、窗口越高看得越多。实测：改动前切歌词，进度条 y 1289→1112、控制键 1353→1176
   （−177px = −88pt）；改动后 cover / lyrics / cover-again 三张图内容段**逐段相同**。
2. **默认不展示待播清单**：`NowPlayingView.showQueueColumn` 由 `true` 改 `false`（顶栏列表按钮仍可展开，
   展开状态不落设置）。实测点开时整窗 26.5% 像素变化（右栏 320 出现）。
3. **侧栏「我的列表」去掉显示全部 / 收起**：删掉 `playlistGroupExpanded` / `playlistExpandButton`，
   列表恒定全展开，靠侧栏自身 ScrollView 滚动；`isPrimarySelected` 随之简化（只剩图标栏那一档退回一级「播放列表」）。

三处都在 `build/Overtone.app` 验证后覆盖安装到 `/Applications`（**没有退出使用者正在跑的实例**：
覆盖 bundle 不影响已运行进程的 inode，下次启动才生效；备份在 `/tmp/Overtone-installed-backup2.app`）。
