Overtone UI 重新设计 v2 · 设计规范与高保真预览

为「自建音乐库」重做一套安静、统一的界面

Overtone 是 macOS 上的 Jellyfin 音乐客户端。本次重设计解决六个结构性问题：缺首页、缺设置页、侧栏职责混杂、令牌不收敛、窄窗口丢导航、可访问性欠账。交付物为设计令牌、组件库、六个核心页面稿与验收清单。

设计目标

G1 · 一屏找到想听的以首页为枢纽，继续播放 / 最近添加 / 最常听前置验收：冷启动 → 开始播放 ≤ 2 次点击（现状 ≥ 3 次）
G2 · 一套令牌，全页一致圆角 6 档、阴影 3 档、选中态 1 套语义验收：新页面 0 处硬编码色值 / 圆角
G3 · 窄窗不破版、不丢导航5 档断点，侧栏降级为图标栏而非消失验收：520pt 窗口仍可「选库 → 选专辑 → 播放」

目标用户

主用户 · 自建媒体库的收听者

25–45 岁，macOS 13+，NAS / Jellyfin 自建，曲库 1k–50k 首。窗口常开半屏边工作边听。要「快、静、稳」→ 导航常驻、动效克制、播放控件不消失。

次用户 · 家庭共享成员

同服务器多账号，偶尔切换，媒体库由他人维护。→ 设置页需「服务器与账号」分组，切换账号不清本地播放列表。

约束型用户 · 必须被照顾

外网穿透 / 弱网（音质与缓存开关）、VoiceOver / 键盘用户（hover 不能是唯一入口）、弱视（动态字号 + 4.5:1 对比度）。

信息架构：旧 → 新

现状（6 个问题）

  • P1 无首页启动直接落到「资料库 / 歌曲」列表
  • P2 无设置页退出登录只是侧栏底部 28pt 图标
  • P3 侧栏混杂搜索与「收藏/最近/最常」同为一级，播放列表无限平铺
  • P4 令牌不收敛圆角 7 种、阴影 3 套、选中态两种语言
  • P5 窄窗策略粗暴仅 2 档，<860pt 时侧栏完全消失
  • P6 可访问性欠账hover 控件键盘不可达；tertiary 对比度 2.6:1

组件库

所有组件共享同一套状态语义：默认 / hover / 聚焦 / 按压 / 选中 / 禁用 / 加载。规则一：hover 不能是唯一入口 —— 键盘聚焦时必须同样出现并可 Tab 到达。

按钮

主按钮 44（小 32），圆角 10，渐变底 + 白字；图标按钮 28 / 32 / 44 三档且必须有 accessibilityLabel。

可访问性基线 · WCAG 2.1 AA

现状最大的两处欠账：hover 才出现的控件键盘不可达、进度条无法键盘调节。以下为硬性验收项。

问题 → 修复对照

项现状v2 要求落地动作
对比度tertiaryText #9CA3AF 白底 2.6:1 ❌正文 ≥ 4.5:1，图标/大字 ≥ 3:1换 #7C8698（3.67:1），且禁止用于正文；正文只用 primary / secondary

验收方式

  • 仅用键盘完成「选库 → 选专辑 → 播放 → 加队列 → 收藏」

  • 系统文本调到 xxLarge，详情页标题换行不裁切
  • 对比度逐项复核（正文 4.5:1 / 图标 3:1）
