# Overtone UI 重新设计方案 v3 ——「基音与泛音」

> 适用产品：Overtone（泛音）—— 原生 macOS Jellyfin 音乐客户端（SwiftUI，macOS 13+）  
> 文档性质：可直接落地的完整 UI 重设计规范（视觉体系 + 信息架构 + 组件库 + 交互规则 + 可访问性基线）  
> 与 v2 的关系：继承 v2 已落地的信息架构（首页 / 五档断点 / 令牌体系），本次完成 **深色模式全量交付、「谐波」视觉母题贯穿、边界状态全覆盖、触达热区升级** 四项增量，并给出逐页线框与状态矩阵。  
> 令牌落地位置：`Sources/JellyfinMac/Theme.swift`（本文所有令牌名与之一一对应）

## 1. 设计背景与目标

### 1.1 产品定位

- **一句话**：官方 Jellyfin 客户端之外的「另一层听感」—— 一个安静、快速、原生质感的 macOS 音乐客户端。
- **名字即设计理念**：Overtone = 泛音，基音之上叠加的谐波。视觉体系直接沿用这一隐喻：界面主体是安静的「基音」（中性表面），品牌色是叠加其上的「泛音」，只出现在有声音、有行动的地方。
- **平台**：仅 macOS 窗口（触控/移动端规则作为未来 Catalyst/iPad 移植的预留基线，见 §5）。
- **非目标**：不做视频模块重设计，不改数据层与播放引擎。

### 1.2 核心用户画像

| 画像                    | 描述                                                        | 关键诉求                            | 设计含义                             |
| --------------------- | --------------------------------------------------------- | ------------------------------- | -------------------------------- |
| **P1 · 自建库重度听者**（主用户） | 25–45 岁，NAS + Jellyfin，曲库 1k–50k 首，窗口常开半屏（700–900pt）边工作边听 | 快（找得到、点得准）、静（不弹窗、不花哨）、稳（多端进度同步） | 播放控件常驻；动效克制且可关闭；一级导航任何窗口尺寸下不消失   |
| **P2 · 家庭共享成员**       | 与家人共用一台服务器，偶尔切换账号                                         | 账号管理清晰，切换不清数据                   | 设置页「服务器与账号」分组；退出登录二次确认           |
| **P3 · 受限环境用户**       | 弱网 / 外网穿透串流；VoiceOver / 键盘 / 弱视用户                         | 音质与缓存可控；全部功能键盘可达                | 音质策略与缓存上限进设置；对比度 AA、热区 44pt、动态字号 |

### 1.3 主要使用场景

- **S1 半屏常驻**：窗口约 700–900pt 宽，边写代码/文档边听 —— 窄窗口不破版、不丢导航是硬约束。
- **S2 全屏浏览**：偶尔放大窗口翻封面墙、逛专辑详情 —— 视觉要有沉浸感但不喧宾夺主。
- **S3 多端续听**：白天手机听到一半，回家打开 Mac 接着听 —— 「继续播放」必须置于首页视觉动线起点。
- **S4 弱网串流**：外网穿透访问家中 NAS —— 音质降级、缓存策略必须可配置。

### 1.4 现有痛点（v2 落地后的存量问题）

| #  | 痛点           | 现状                                         | 影响                      |
| -- | ------------ | ------------------------------------------ | ----------------------- |
| D1 | **深色模式未落地**  | 令牌层已预留 `colorScheme` 分支，但视觉只交付浅色           | 夜间听歌刺眼，与 macOS 系统深色格格不入 |
| D2 | **品牌母题不贯穿**  | 频谱/谐波元素只出现在正在播放页，各页面视觉叙事不连贯                | 产品记忆点弱，换皮后辨识度低          |
| D3 | **边界状态覆盖不全** | 空态/错误态多为临时文案，无统一模板；超限态（超长标题、5 万曲库、缓存上限）无规范 | 极端场景走样、可感知质量不稳定         |
| D4 | **首页层级偏平**   | 各区块视觉权重相同，缺少 Hero 区                        | 冷启动视线无落点，「继续播放」不够前置     |
| D5 | **反馈形式不统一**  | 收藏/加入队列等操作的反馈时有时无，动效令牌存在但应用不一致             | 操作确认感弱                  |
| D6 | **触达余量不足**   | 部分 26–28pt 控件热区偏小，未为触屏预留基线                 | 误触率高，Catalyst/iPad 移植欠账 |

### 1.5 设计目标

| 目标           | 表述                                                       |
| ------------ | -------------------------------------------------------- |
| **G1 双主题同权** | 深色模式完整交付：全部令牌双主题成对定义，切换无硬编码残留，阴影/描边策略按主题分别处理             |
| **G2 母题贯穿**  | 「基音与泛音」谐波分级系统贯穿全部页面：中性表面为基音，品牌色按 L0–L3 强度分级出现            |
| **G3 边界全覆盖** | 四个核心页面 × 空态/加载/错误/超限，16 类状态全部有明确设计，收敛为 5 个复用组件           |
| **G4 触达升级**  | 命中区 ≥ 44×44pt、动态字号 xxLarge 不裁切、VoiceOver 全标签、颜色不作为唯一信息载体 |

### 1.6 设计原则

1. **内容为王**：封面与曲目是主角，界面 chrome 退后 —— 大面积中性表面，装饰性颜色只给「正在发生的事」。
2. **一套令牌**：任何视觉决策先查令牌表；没有令牌先立令牌再使用。页面代码零硬编码色值/圆角/字号。
3. **静而准**：动效有目的（指示因果、维持空间感），时长 ≤ 260ms，全局尊重「减少动态效果」；反馈即时但不打断。
4. **不丢导航**：任何窗口尺寸、任何输入方式（鼠标/键盘/VoiceOver）下，用户都知道自己在哪、怎么回去。

### 1.7 成功衡量标准（3 条）

1. **效率**：冷启动 → 开始播放 ≤ 2 次点击（P95，覆盖首页与搜索两条路径）。
2. **一致性**：双主题令牌覆盖率 100%（全局扫描 0 处硬编码样式），正文对比度全部 ≥ 4.5:1（脚本复核）。
3. **健壮性**：五档窄窗 × 动态字号 xxLarge 全组合下，核心任务零裁切、零导航丢失；仅用键盘（Tab + 空格 + ⌘ 系）可完成全部核心任务。

## 3. 导航与交互逻辑

### 3.1 信息架构与页面跳转关系

```
                    ┌──────────┐
                    │  登录页  │
                    └────┬─────┘
                         │ 连接成功
                         ▼
┌────────────────────────────────────────────────────────┐
│ 侧栏一级导航（5 项，替换栈，互不返回）                  │
│                                                        │
│  首页 ──push──> 专辑详情 ──push──> 艺人详情             │
│  资料库 ─push─> 专辑/艺人/播放列表详情                  │
│  播放列表 ─push─> 播放列表详情                          │
│  正在播放（全局单例页，不进栈）                          │
│  搜索 ─push─> 各类详情（返回 = 回到搜索结果）           │
│  ··················································    │
```

- **一级切换** = 替换栈（`stack = [page]`），无返回按钮，侧栏高亮指示当前位置。
- **二级推进** = `push(page)`，详情页顶部面包屑返回栏。
- **设置** = 独立窗口（⌘,），不破坏主窗口导航栈。

### 3.2 主导航形式

- **形态**：完整侧栏 240pt（可拖拽 180–320）⇄ 窄窗降级 64pt 图标栏（**仅图标**，悬停 tooltip 显示名称；键盘/读屏走 `accessibilityLabel`），W1 档可临时展开 240pt 抽屉（40% 遮罩，点击外部或 Esc 收起）。

- **快捷键**：

| 快捷键 | 行为 |
|---|---|
| `⌘F` | 聚焦搜索框（任何场景） |
| `空格` | 播放 / 暂停（输入框聚焦时放行给输入框） |
| `⌘→ / ⌘←` | 下一曲 / 上一曲 |
| `⌘[` / `Esc` | 返回上一级 / 收起抽屉 |
| `⌘1 … ⌘5` | 切换一级页（首页/资料库/播放列表/正在播放/搜索） |
| `⌘,` | 打开设置 |
| `⌘↑ / ⌘↓` | 播放列表详情内上移/下移选中曲目 |

| `⌫` | 编辑态删除选中项 |

|---|---|---|

### 3.4 反馈方式与微交互规则

| 场景 | 反馈 | 动效令牌 |
|---|---|---|
| 悬停 | 底色切换 `surfaceHover` | `micro` 120ms |
| 按压 | 缩放 0.97 | `micro` 120ms |
| 点击播放 | 迷你播放条上移 12pt + 淡入；行变选中态；封面角标变暂停 | `page` 260ms / `spring` |
| 加入队列 / 收藏 | Toast（底部居中，高 44，3s 自动消失，不遮挡播放条——整体上移 88）；心形填充 | `base` 200ms + `spring(0.3, 0.6)` |
| 页面切换 | 位移 8pt + 淡入；列表错落入场 30ms×index（≤10 项） | `page` 260ms |

| 窗口拉窄 | 侧栏 → 图标栏宽度过渡，无布局跳变 | `base` 200ms |

| 破坏性操作 | 确认弹窗（危险按钮 + 说明后果） | `base` 200ms |

## 4. 视觉体系

### 4.1 设计概念：「基音与泛音」

- **基音**（约 90% 的界面）：中性表面与灰阶 —— 安静、退后、承载内容。
- **泛音**（约 10% 的界面）：品牌色，按强度分级，只出现在「有声音 / 有行动」的地方：

| 谐波强度 | 定义 | 用途 |
|---|---|---|
| **L0 纯基音** | 无品牌色 | 表面、文字、分割 |
| **L1 泛音染色** | `brandTint`（主色 8% 透明度） | 选中行底、焦点光晕、hover 强调 |
| **L2 泛音实底** | `brand500` 实底 | 主按钮、分段选中、开关开启 |
| **L3 泛音律动** | `brandGradient` + 青色频谱 | 正在播放页、Logo、空态插画点缀 |

- **第二谐波（泛音青 `overtoneTeal`）**：专属于「正在发声」的语义 —— 频谱柱、正在播放律动、歌词高亮的辅助色。装饰用，不作正文色。
- **正在播放页氛围色**：取封面主色生成低饱和背景渐变（透明度 ≤20%），失败时回落 brandGradient；前景对比度由遮罩层保证。

### 4.4 圆角 / 间距 / 阴影 / 焦点

- **圆角 6 档**：`xs 4` · `sm 6` · `md 10` · `lg 14` · `xl 20` · `full 999`
  小控件/Chip 6 · 输入框/按钮 10 · 卡片 14 · 胶囊/圆形 full；**窗口、玻璃悬浮面板与全部封面统一取 `md 10`**（§7.2）。
- **间距 4pt 基线**：`2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48`
  卡片内距 16；区块间距 32；页面水平边距 16/20/24/28/32 按断点。
- **阴影 3 档**（基色 `#10141C`）：
  - `e1` `0 1px 2px · 6%` 卡片静态
  - `e2` `0 4px 8px · 8% + 0 1px 2px · 6%` hover / 下拉 / 面板
  - `e3` `0 14px 28px · 12% + 0 3px 6px · 6%` 正在播放大封面、弹窗
- **焦点环**：1px `brand500` 描边 + 3px 28% 光晕（`FocusRing` 修饰符），替代系统蓝框，键盘可见。

## 5. 适配与可访问性

### 5.1 断点策略（macOS 五档，未来移动端同规则复用）

设计以**内容区宽度 W**（窗口宽 − 侧栏宽）定义；实现按窗口宽阈值（与 `Theme.swift` 现行实现一致，单调无震荡）：

| 档位 | 内容区 W | 窗口宽 | 侧栏 | 页边距 | 网格 min | 详情页封面 | 播放条 | 正在播放 |
|---|---|---|---|---|---|---|---|---|
| **W0** | <640 | <640 | 图标栏 64，仅图标 + tooltip | 16 | 140 | 纵向堆叠 140 | 68 两区（高度与宽窗一致） | 单列 + 待播抽屉 |
| **W1** | 640–819 | <860 | 图标栏 64，仅图标 + tooltip（可展开抽屉） | 20 | 150 | 纵向堆叠 160 | 68 隐藏音量 | 单列 + 待播抽屉 |
| **W2** | 820–1023 | <1100 | 完整 220（可拖拽） | 24 | 160 | 横向 220 | 68 隐藏时间码 | 单列 + 待播抽屉 |
| **W3** | 1024–1339 | <1420 | 完整 240 | 28 | 180 | 横向 220 | 三区完整 | 左主区 + 右栏 320 |
| **W4** | ≥1340 | ≥1420 | 完整 240 | 32（内容 max 1440 居中） | 200 | 横向 220 | 三区完整 | 左主区 + 右栏 320 |

- **播放条降级按「播放条自身实测宽度」而不是窗口档位**（2026-10-02 修正）：侧栏宽度可拖拽 180–320 或降级成 64pt 图标栏，同一窗口档位下播放条可用宽度能差 250pt 以上。实测阈值：**≥820** 三区（左信息 ≤220 + 控制 + 右音量 176）/ **≥940** 追加两侧时间码 / **<620** 紧凑（内边距 20→12、区间距 16→8、进度条最小宽 160→56）。左区与音量区都用 `maxWidth` 而非固定 `width`，窄了能一路压到「封面 + 少量标题」。


### 5.2 安全区与窗口 Chrome 适配

- **顶部**：透明标题栏 + `fullSizeContentView`；侧栏悬浮面板（外边距 10）把红黄绿三键包进面板内 —— 三键位置由 `WindowManager.moveTrafficLights` 按侧栏形态摆放（完整侧栏 x=20 起 / 图标栏 x=14 起），面板内内容顶部预留 34pt（`windowChromeHeight`），顶栏 64pt 已包含该区，内容不可侵入。
- **底部**：迷你播放条为常驻底缘（56/68pt），滚动内容底部预留等高内距防遮挡；Toast 在播放条上方 88pt。
- **移动端预留规则**（Catalyst/iPad 移植时生效）：侧栏可延伸入安全区背景，内容区一律使用 `safeAreaInsets`；播放条贴 `bottom safe area`；横屏窄宽自动落 W0–W2 档，断点规则不变。

### 5.3 点击区域（≥44×44pt）

1. **所有可交互元素命中区 ≥ 44×44pt**：视觉尺寸 28/32 的图标按钮通过 padding 扩展命中区（视觉不变、热区达标）。
2. 列表行高 44–56 天然达标；相邻可点元素间距 ≥ 8pt。
3. 例外：行内文本链接热区随行高（≥44），音符/封面角标等纯装饰元素不响应点击。
4. 指针场景（macOS）精度高，但统一 44pt 底线以降低误触并为触屏移植预留基线。

### 5.4 动态字号（Dynamic Type）

- 全部字号相对化（`ScaledMetric` + `relativeTo` 映射，见 `Theme.TextStyle`），跟随系统文本大小。
- 上限 `xxxLarge`：布局允许换行、不允许裁切；详情页标题最多 2 行 + 省略号；网格卡片文字区自适应高度。
- 图标、封面等媒体尺寸固定不缩放，避免布局爆炸。

### 5.5 颜色不作为唯一信息载体

| 语义 | 颜色通道 | 冗余通道（必须同时存在） |
|---|---|---|
| 正在播放 | 主色文字 + teal 频谱 | **频谱柱图标动效**（Reduce Motion 下静止等高三柱） |
| 收藏 | `favorite` 红粉 | **心形填充 vs 描边**形态差异 |
| 错误 | `danger` 红 | **警示图标 + 文字说明** |
| 成功 | `success` 绿 | **对勾图标 + 文字** |
| 选中行 | `surfaceSelected` 底 | **3pt 左侧指示条 + 字重 600** |
| 播放/暂停按钮 | 主色底 | **图标形态切换**（▶ / ⏸） |

### 5.6 无障碍标签与 VoiceOver

| 规则 | 落地 |
|---|---|
| 图标按钮 100% 有 `accessibilityLabel` | 「播放」「下一曲」「加入队列」「更多操作」…… |
| 曲目行合并为单元素朗读 | `accessibilityElement(children: combine)`：「第 3 首，曲名，艺人名，3:42」；当前曲追加「播放中」 |
| 播放控制带状态值 | 播放按钮 `accessibilityValue` = 播放中 / 已暂停 |
| 进度/音量可增量调节 | 原生 `Slider` 或 `.accessibilityAdjustableAction`（进度 ±5s，音量 ±2%） |
| 开关播报状态 | value = 开 / 关 |
| 语义结构 | 区块与设置分组标题 `.isHeader`，支持 VoiceOver 转子快速跳转 |
| 装饰元素 | 插画、频谱装饰 `accessibilityHidden(true)` |
| hover 控件键盘可达 | 收藏/更多等 hover 控件由 `@FocusState` 驱动显隐，Tab 可达（不只靠 `hovered`） |

## 7. 增补：Liquid Glass 适配（macOS 26/27）

> macOS 26 起 App 按「当前设计语言」绘制（本项目 `Package.swift` 的 `-platform_version` linker 设置正是为了拿到它）。本章把 v3 体系升级为「玻璃 chrome + 实体内容」双层结构，HTML 预览（`UI-Redesign-v3-preview.html`）以 `backdrop-filter` 模拟，含材质开关与无障碍回退演示。

### 7.1 材质令牌（新增 Material Tokens）

| 令牌 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `glass.thin` | `rgba(255,255,255,.42)` + blur 20/sat 1.4 | `rgba(26,29,38,.40)` + blur 20/sat 1.4 | 顶栏、分段容器、次级控件底 |
| `glass.regular` | `rgba(255,255,255,.55)` + blur 28/sat 1.55 | `rgba(26,29,38,.52)` + blur 28/sat 1.55 | 侧栏、抽屉、搜索框、胶囊按钮 |
| `glass.thick` | `rgba(255,255,255,.74)` + blur 32/sat 1.6 | `rgba(30,34,44,.72)` + blur 32/sat 1.6 | 播放条、菜单、弹窗、Toast |
| `glassBorder` | `rgba(255,255,255,.62)` | `rgba(255,255,255,.10)` | 玻璃层 1px 描边（替代浅色阴影分层） |
| `glassHighlight` | `inset 0 1px 0 rgba(255,255,255,.70)` | `inset 0 1px 0 rgba(255,255,255,.10)` | 顶部镜面高光（specular） |
| `ambient` | 封面取色 wash（4 组 radial，α .24–.38） | 同左（α .10–.30） | 玻璃之下的氛围层，让透材质「有东西可透」 |

### 7.2 使用规则

1. **双层结构**：chrome（侧栏 / 顶栏 / 迷你播放条 / 抽屉 / 菜单 / 弹窗 / Toast / 次级控件）= 玻璃材质；内容层（卡片、表格、设置卡、曲目行）= 不透明 `surface`。玻璃只给「框」，不给「内容」。
2. **悬浮化 + 统一圆角**：侧栏与播放条从贴边改为**浮动面板**（外边距 10–12pt）；窗口、顶栏、侧栏、播放条、抽屉与**全部封面统一圆角 R=10（`md`）**，不做同心圆角递减；面板内控件沿用既有令牌（列表条目 6、按钮/输入 10）。
   - **实现要点（踩过的坑）**：`.padding(外边距)` 必须写在 `.glassPanel(...)` **之外**。写在里面时玻璃会铺满含 padding 的整块，面板重新贴住窗口边缘 —— 观感与「贴边侧栏」无异（2026-10-02 修正）。
   - **红黄绿三键要跟着面板走**：面板外边距 10 + 圆角 10 → 左上角圆心在 (20, 20)，系统默认按钮位置（首键左上角 (8, 8)）正好落在圆角**外侧**。完整侧栏把三键移到 (20, 20)、间距 7；图标栏面板只有 64pt 宽，三键收到 x=14 起、间距 4（与 preview 窄窗 `left:18px;gap:6px` 同构）。窗口缩放会重置标题栏布局，需要在 resize 后重新摆放。
3. **内容列宽度是硬约束**：内容列 = 窗口宽 − 侧栏块（外边距 + 面板宽）。任何子视图（顶栏 / 播放条 / 页面）的最小宽度一旦超过它，`HStack` 会把整列按最小宽度铺开并溢出到窗口右边缘，表现为「顶栏搜索框、播放条右半、页面右边缘被裁掉」。因此：① 内容列显式给定宽度；② **播放条按自身实测宽度降级**（≥820 三区 / ≥940 显示时间码 / <620 紧凑），不能用窗口档位 —— 侧栏宽度可拖拽 180–320，同档位下播放条可用宽度能差 250pt 以上；③ **页面滚动体钳制宽度**（`.pageBodyWidthClamp()`，即 `minWidth: 0` 弹性帧）—— 页面内部还有一次最小宽度协商（滚动体 → 页面 VStack → 顶栏 / 面包屑），滚动体把内容最小宽度上报给页面时 chrome 会被一起撑宽，顶栏 / 面包屑玻璃面板的右缘连同 12pt 外边距与圆角被窗口右缘裁掉（938pt 窗口 + 270pt 侧栏 → 内容列 658pt，2026-10-03 截图复现并修正）；④ **详情页操作行按可用宽度换行**（`FlowLayout`）—— 五项一行摆开最小 ≈412pt，窄内容列下必须换行，不能把页面最小宽度顶到内容列之上。
4. **氛围层**：窗口底加封面取色渐变 wash（`ambient`，透明度 ≤38%），玻璃之下必须有可透内容；正在播放页的取色背景即为同一资产。
5. **性能预算**：同屏可见 blur 层 ≤ 4；禁止对 `backdrop-filter` 本身做动画（显隐用透明度过渡）；滚动中的 sticky 表头用 `glass.thick` + blur 20。
6. **文字对比度**：玻璃上的正文仍用 `textPrimary`（材质不透明度 ≥55% + saturate 时实测 AA 保持）；若氛围色过艳，提升到 `glass.thick` 而非降低氛围透明度。

### 7.3 可访问性回退（必须实现）
